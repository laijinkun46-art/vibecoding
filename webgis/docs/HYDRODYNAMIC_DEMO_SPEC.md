## 一 项目目标

在现有 WebGIS 中，以研究区内整条邕江河段及两岸地形为范围，构建教学用二维水动力情景，展示水流传播、水面上涨、漫岸扩散和退水。最终画面应流畅、连贯，能够暂停、拖动时间轴、调整播放倍率并查询水深和流速。

保留真实 DEM 和现有河流位置；允许缺失的河床、水文及摩阻参数采用明确标注的模拟值。无需收集研究区外的上游流域资料，不以取得真实流量、水位或历史验证资料作为启动演示的前提。

对外统一表述为“基于真实地形和假设参数的洪水动态情景模拟”。不声称精确复现2024年洪水，不将模拟参数和模型结果标作实测资料。

用户已明确的目标为整条河段、允许模拟参数、优先保证动态效果。本稿将其整理为实施和验收要求；新增本稿不代表模型、效果或性能已完成。

## 三 计算范围

复用现有 AOI，即研究区域边界。现有边界为108.23～108.44°E、22.73～22.85°N，最终以实际文件为准。首版以现有 AOI 为完整地形及候选计算范围，最终计算域在 AOI 内覆盖整条邕江主线和两侧允许过水的地形。

旧审计记录主线约33.68km；实施时以当前河流文件重新核对长度和覆盖。不能用7km的C03替代最终全河段成果。C03可以先进行短历时试算，验证程序后再扩展。

只处理研究区内部及其边界，不额外建立研究区外的上游汇水区，不下载外部数据。若AOI边缘发生出流，应在结果中体现研究区截断边界，面积统计限定于域内。

计算区域需要包含河道周围的地形，不能只沿中心线画一条固定宽度的蓝色带。若为降低计算量裁减外围高地，应记录裁减依据，保留全主线、可能过水区域和必要边界通路，并检查裁减前后的敏感性。

## 四 技术职责与数据链

沿用 Vue、CesiumJS、Three.js、ECharts、FastAPI 和既有 Python GIS 工具。

| 部分 | 职责 |
| --- | --- |
| Python GIS | 计算域、派生地形、参数区域和网格输入准备 |
| ANUGA | 作为首选二维水动力求解器，计算随时间变化的水深、水面高程和水平速度 |
| FastAPI | 只读提供已生成的结果清单、帧数据和点位时序 |
| CesiumJS | 在现有唯一地图场景中显示地形、动态水面、淹没范围及流动效果 |
| Three.js | 按需复用向量或纹理工具，不承担水动力求解 |
| ECharts | 显示淹没面积、水深和流速过程 |

数据链为：现有地形和河线 → 假设河床与边界参数 → 二维网格及求解 → 结果检查 → 帧转换与缓存 → Cesium连续播放。

采用提前计算、连续播放的方案，浏览器不在每个显示帧中求解整条河段。环境兼容性在建模阶段验证，不预先承诺ANUGA已经可运行；确需新增依赖时按项目规则办理，不替换现有API或GIS环境。

若求解器无法使用，先报告实际障碍和可审阅替代方案。纯水位插值或纹理动画只能标为视觉演示，不能静默替代本稿要求的水动力计算。

## 五 数据与模拟参数

| 输入 | 使用规则 |
| --- | --- |
| DEM | 复用Phase 2的30m地形，源文件只读；模型地形另存 |
| 河流中心线 | 定位整条邕江河段，不直接作为实测河宽或实际流向证据 |
| 河床 | 允许参数化宽度、深度和纵坡；单独保存为假设地形，不修改源DEM |
| 流量 | 允许构造平滑的基流、涨水、洪峰和退水过程，单位m³/s |
| 下游边界 | 允许采用假设水位过程或经检查适用的开放边界，记录选择理由 |
| 糙率 | 用参数表达河床和地表阻力，允许简化分区并进行小范围敏感性比较 |
| 初始条件 | 设定初始水面与速度，必要时预热，减少启动突跳 |
| 降雨 | 可复用CHM_PRE历史降雨或采用合成雨型，清楚区分两者 |

所有假设参数保存名称、数值或序列、单位、适用区域、设置理由和来源类型。初版可由实施者给出一套可运行默认值，不要求用户逐项提供真实资料；交付时列出这些默认值。

研究区外水文调查不属于本任务，但有限计算域仍需边界条件。程序在主线穿越研究区边缘的位置设置假设入口和出口，侧界按地形和过水关系配置，不把整个周界一律设为封闭墙。节点顺序不证明实际流向；如采用约定流向，明确标为情景假设。

主槽现有DEM平台不等于河底。参数化河床应与初始水位、入口流量和出口条件配套检查，避免不合理地形或边界造成数值不稳定。可以调整情景参数产生可辨认的涨水与漫岸过程，不通过逐帧修改结果伪造过水。

使用历史CHM_PRE时保持20:00至次日20:00气象日语义，逐日量如均匀分配为雨强需记录假设；转换为m/s时除以1000和86400。合成降雨不绑定2024年观测日期。局部降雨不作为上游流量的直接换算依据。

水平计算继续使用EPSG:32649米制坐标。高程沿用既有EGM2008解释，模型水位采用相同基准；Cesium显示需统一相对高程处理并保留基准说明。三维拉伸仅影响画面，不改变查询水深、流速或统计。

## 六 动态效果与交互

第一版交付一个完整的基础情景，体现河道有水、涨水沿河传播、局部漫岸扩散、洪峰和退水的连贯过程。后续可复用同一模型增加强弱不同的来水情景，不以首版大量参数面板代替完整效果。

### 水面和淹没

水面按模型逐点高程变化，不能让全研究区只跟随一个统一高度升降。河道向两岸的扩散由模型水深及干湿状态驱动；地形高地应形成可见约束，范围外和无效数据区域不绘水。

河流水体在合理初始湿区内连续可见；淹没边缘随时间推进，避免整块多边形突然出现。退水使用对应模型时刻结果，不倒放或重算静态水位范围冒充退水过程。

### 流动表现

用模型速度向量驱动粒子、流线状纹理或箭头，表现弯道方向、局部快慢和随时间变化。粒子沿时变流场运动形成的轨迹称为迹线，不能将其当作流量或淹没判据。

静水、干地、无效区域不强行制造运动；粒子不能穿越干地和高地。波纹作为装饰层，不用于计算流速、水深或面积。

### 时间与查询

共用一个模拟时间，水面、流动效果、淹没范围、面积曲线和点位查询保持同步。支持播放、暂停、重播、拖动时间轴及0.5、1、2倍播放；演示压缩时长与模拟历时分别标明。

暂停冻结模拟过程；拖动后只显示新时刻有效结果，取消过期请求，并重置粒子历史。浏览器后台暂停，恢复时不突然跳过大量模拟时间。

点击位置可查询水深、流速及时间曲线；域外和缺测返回明确状态，不用0代替。历史降雨日期、合成情景历时和旧S01至S04情景序号分别解释。

## 七 连贯播放与性能目标

求解时间步、结果输出间隔和显示帧率是三个不同概念。求解器可用小时间步保持稳定，按需要输出结果，Cesium再连续显示相邻时刻。

采用相邻帧预加载、有限缓存和可控粒子数量，复用网格与渲染资源；避免每帧重建全部河段几何。缓存缺帧时暂停模拟时间并提示加载，不让粒子继续而水面停住。

显示插值不能凭空填补缺测或把水跨越干地、高地平滑过去。干湿转换需单独处理；显示水深、水面高程和湿区判定保持一致。首次淹没时间和面积统计以模型输出及明确阈值计算，插值展示不得宣称提高地形或计算精度。

以下为拟定验收目标，尚未实测：

| 项目 | 检查方法与目标 |
| --- | --- |
| 连续性 | 在全河段视角完整播放涨水至退水，无明显帧间跳水、白闪或大块闪现 |
| 帧率 | 本机桌面浏览器、固定1920×1080视口、预热后播放2分钟，基础情景平均至少30fps；60fps作为优化目标 |
| 停顿 | 分开记录资源加载等待和已缓存播放的停顿，正常播放无反复长于0.5秒的可见卡顿 |
| 交互 | 已缓存时刻拖动后目标0.5秒内更新；缺帧明确提示，不显示错误时刻 |
| 稳定性 | 连续播放及反复拖动10分钟，无崩溃、无持续累积的显存或内存增长趋势 |
| 低性能设备 | 优先减少粒子、装饰波纹和显示细节，保留模型时间、水面和淹没范围正确性 |

记录测试机器、浏览器、窗口尺寸、视角、数据规模及粒子数量。若未达标，报告实测值和瓶颈，不将目标写成通过。新动态模式需检查旧24fps刷新限制是否适用，不能直接沿用旧限制却宣称达到30fps。

## 八 模型与结果验收

允许假设参数不免除基本计算检查。至少验证静水平衡、非负水深、有限速度、干湿转换及水量收支。质量守恒指“初始水量加流入和降雨，减去流出及其他损失，应与当前水量相符”；实施时在计算前约定误差阈值，记录误差，不能看完结果再放宽标准。

模型结果需保存水深h、水面高程stage、速度u和v、干湿和有效掩膜、模拟时间，以及统计信息。ANUGA原始输出如采用动量变量，需核对存储位置与单位后转换速度，并处理浅水除法，避免岸边产生虚假高速。

验证同一时刻图层、粒子和查询一致；用已知速度和时间的样例检查粒子位移及播放倍率。水体速度不等于淹没前锋传播速度；首次淹没时间应注明水深阈值与结果输出间隔。

最终验收同时看模型基本合理性和画面效果：完整河段覆盖、完整涨落过程、可解释的漫岸位置、连续交互、性能记录及模拟参数说明。没有历史观测时不评定2024年事件复现精度。
