## 一、项目概述

项目名称：基于既有水动力结果的南宁邕江全河段水面视觉优化。

项目类型：现有本科GIS课程设计的增量开发。

项目目录：`C:\Users\ly5it\vibecoding\webgis`。

研究区域：现有AOI内整条邕江主线及两岸可能过水地形，约33.68km主线，以当前数据为准。

当前基础：已有全河段模型结果、Cesium动态水面、双帧插值、流动跟踪点、时间轴及点位查询。具体版本与可运行状态在实施开始时检查，不依据历史报告直接认定通过。

最终成果：全景连续显示涨水、漫岸与退水，近景水面具有自然颜色、细波纹、弱反光和柔和岸线；同时保留水深、流速分析及可核对的模型数值。

统一说明：基于真实地形和假设参数的洪水动态情景模拟，不能标作实测或2024年洪水精确复现。

## 二、研究目标

1. 改善单元水面矩形拼接、台阶和岸线闪烁，使完整河段视觉连贯。
2. 增加自然水面样式，使用模型流场驱动纹理方向和运动强弱。
3. 完成自然、水深、流速三种样式，共用一个水面渲染对象及模拟时间。
4. 保留双帧插值和缓存，确保暂停、回拖、倍速及缺帧恢复时画面一致。
5. 在原始模型、统计和查询数据不变的条件下改善外观。
6. 完成实际运行、同视角对照、性能和稳定性测试，提供可打开的演示及验收记录。

优先级为：数据及高程正确 → 岸线和水面连续 → 时间同步 → 自然材质及流动细节 → 性能调优。实现时不以光效遮盖几何或时间错误。

### 地形与研究区

复用已有AOI、Phase 2 DEM、模型派生床高和地形显示逻辑。模型计算使用米制投影及既有EGM2008高程解释，地图显示应采用一致的转换约定。

源DEM、模型床高、原始帧、现有网页帧及旧静态成果只读。需要新增显示辅助数据时，另存有版本的文件，说明映射方法和来源，不覆盖原资产。

### 纹理与视觉参数

优先使用已经安装的Cesium法线纹理及已有水体代码。颜色、透明度、波纹尺度、反光强弱、视觉时间缩放和粒子数属于显示参数，集中配置，不写入求解参数文件。

首版无需下载数据、引入新的底图、添加字体、安装视觉插件或新增依赖。历史CHM_PRE降雨继续保持原有展示，本轮不转为新强迫、不重新求解。

## 四、核心分析方法

### 1. 高程与空间显示

先核对地形、床高、水面stage、垂直拉伸和显示偏移。修正坐标或取样不一致，再处理深度冲突；不能通过不断抬高水面掩盖穿地。

建立真实地理邻接和共享显示顶点，处理自适应粗细单元接缝。显示重建限定于有效、可连通邻域，不跨高地、干地及分隔线平均取值。

当前按单元序号打包的纹理不具有地理邻接关系，保持最近邻读取，禁止简单开启LINEAR过滤。需要平滑时通过显式邻接映射或独立显示数据完成。

细分只改善显示，不提高源数据或计算精度。默认不将水绘制到原始有效湿单元范围之外；若无法安全重建岸线，保留可核对的原单元模式并明确剩余限制。

### 2. 岸线与干湿状态

统一读取清单湿深门槛，当前记录为0.05m。浅水渐隐可从0.05～0.20m开始调试，属于视觉参数，不改变淹没统计门槛。

低于门槛不绘水，岸内渐隐，域外和无效区域透明。只调整单元恒定颜色的透明度不能消除矩形轮廓，需与显示网格处理配套。

### 3. 水面着色与流动

自然样式采用低饱和蓝绿或灰绿色，双尺度法线波纹、距离衰减和弱反光。波纹扰动光照，不改平均水面stage；首版不做额外反射场景和高成本倒影。

流动方向及强弱取自当前模型u/v，沿用并核对投影方向转换。使用连续相位或可重建的相位状态，避免速度改变或纹理循环时跳变。

水深和流速样式使用固定色标、数值范围及单位，弱化装饰光照，避免每帧自适应色标改变颜色含义。

### 4. 时间插值与资源复用

所有水面、波纹、粒子及界面状态共用模拟时间。装饰波纹采用明确的视觉时间缩放，暂停冻结，拖动后可直接定位，不要求从头播放。

沿用相邻帧预取、有限缓存和固定GPU资源。普通渲染帧只更新必要参数，模型帧对更换时才上传数据，不逐帧重建全河段Primitive。

## 五、系统功能

1. 自然水面、水深分析、流速分析三种样式切换。
2. 连续的水面上涨、漫岸、洪峰和退水展示。
3. 模型流场驱动的水纹及可开关跟踪点，必要时使用有限短迹线。
4. 全河段视图、弯道斜视和漫岸低地近景检查入口，复用已有相机能力。
5. 播放、暂停、重播、回拖及0.5、1、2倍播放。
6. 现有面积统计、点位水深和速度查询、过程曲线继续可用。
7. 原单元边界或等价调试对照开关，便于核对显示平滑。
8. 缺帧加载提示、错误提示、低性能画质降级及模式切换资源释放。

静态S01至S04、降雨、原有地图图层和基本定位功能继续保留。自然样式不需要关闭模型查询。

## 八、验收标准

### 数据正确性

优化前后核对模型及旧成果内容指纹；固定位置、固定原输出时刻的查询值和面积一致。记录高程基准、视觉偏移和拉伸处理，装饰效果不改变模型值。

对照原湿区及原单元边界，检查岸线不向无效或干单元扩张，不穿越高地；粗细单元接缝无明显裂缝。若有无法消除的网格分辨率限制，明确列出位置和原因。

### 视觉与交互

固定三种时刻：基流、洪峰、退水；固定三类视角：全河段、河弯斜视、岸边近景。使用同底图、同镜头、同拉伸的新旧截图及短录屏进行比较。

自然模式应明显减弱块状平涂、重复纹理和白点带；无大片白色高光、厚光圈、持续岸线闪烁或悬浮水面。分析模式保持固定图例。

暂停后水面、波纹和粒子冻结；拖动只显示目标时刻，倍速一致。缺帧时统一等待，不允许粒子继续而水面停住。切回旧静态模式仍可操作S01至S04。

### 性能与稳定性

目标为本机桌面1920×1080、预热后播放120s平均不低于30fps，争取60fps；记录帧间隔P95、最长停顿及测试环境。不能引用旧交付报告的帧率充当本次实测。

已缓存时刻拖动目标0.5s内恢复；正常播放无反复超过0.5s的可见停顿。至少进行10分钟播放、拖动和样式切换检查，记录JS内存、缓存和可测GPU资源数。未测显存就明确说明，不宣称全部资源验证通过。

性能不足时先降低装饰波纹、粒子和显示细节，不关闭干湿约束或数据验证。无法达到目标时记录实测结果和剩余瓶颈，不写“全部通过”。

### 构建与回归

在`frontend`目录运行项目规定的`npm.cmd run build`。执行与改动有关的逻辑检查、已有动态浏览器回归和本次补充检查；先查看脚本输出位置，新增验收记录另存，避免覆盖历史报告和截图。

实际浏览器中检查WebGL报错、图层残留、暂停恢复、快速拖动、质量切换及资源释放。构建成功不等于视觉验收成功。
