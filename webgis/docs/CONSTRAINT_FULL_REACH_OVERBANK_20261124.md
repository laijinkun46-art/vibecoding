## 一、目标与交付边界

在现有「全河段模拟」里，从 `full_reach_v2` 接续，在研究区内整条约 33.68 km 邕江及两岸计算并展示水在河槽内传播、越岸进入相邻低地、再沿出口退去或在低洼区滞留。全景能辨认影响范围，城区近景能看到原本未淹位置随后被覆盖。同一界面保留真实由模型计算的水深、流速、水面高程和点位过程。

保留已经完成的 12 秒「陆地淹没」独立演示、其深链接 `?demo=land-flood`、S01–S11 静态成果与 CHM_PRE 历史降雨展示。静态情景可用于识别值得观察的低地及对照画面，尤其是 85 m 场景。该场景相对 75 m 新增的 109.13 km² 属于静态等水位假设，二维试验不以该面积作为拟合目标，也不把这张淹没图加载成二维结果。

事件背景为 2024 年 9 月南宁洪水。新场景对外称为「基于真实地形和假设参数的全河段二维洪水情景」。已有逐日降雨保留为历史背景。没有已验收的模型降雨强迫时，继续以独立合成来水作为驱动。参数、模拟时刻和演示时长分别标注，避免与实测水位、历史时钟或预报混淆。

## 二、内部执行顺序

### A 先定位现有漫岸不足

读取适用 `AGENTS.md`、项目说明、最新 Git 状态、已验收运行清单与参数。核对 DEM、AOI、既有地形与参数成果以及网页帧的指纹，记录当前差异。复用现有二维求解器、离线预计算、FastAPI、Cesium 单场景和水动力交互。

以 `full_reach_v2` 展示时刻 0 h、16 h、22.5 h、60 h 为初始对照，核对 W 端来流、E 端尾水、侧泄、床面和地形过渡、网格尺度与水量台账。既有成果在理想河槽及过渡带外，湿区峰前增加约 2.128 km²、峰后减少约 2.001 km²。见[原运行验收数据](../data/processed/hydrodynamics/runs/full_reach_v2/validation.json)。先查清限制来自通量、尾水、岸顶地形、侧界、网格还是画面取景。选择至少两个靠近街区或道路的代表性低地，记录进水可能经过的岸段、阻隔高点、距域边界距离和观察点坐标。优先覆盖不同岸侧或不同河弯。

### B 用独立运行试验来水与漫岸连通

1. 复用现有求解器和计算网格。建立有版本的参数配置，先分别比较平滑入流的峰值与历时、尾水涨落与时间差。选择有解释依据的组合后先跑短时或粗网格试验，再跑完整的全河段情景。W→E 仍是情景约定，检查 E 端回流和低地侧泄的作用，避免边界回水伪装成从河槽越岸。
2. 只有在剖面、相邻格网或地形检查表明连通被离散错误阻断时，才考虑局部加密或独立派生地形修正。保留其他 DEM 和主要地形障碍。记录改动位置、理由及前后高程，对照相同来流下的结果差异。不能通过普遍削低两岸、填补未知地形或直接把静态湿面写入求解状态扩大漫岸。
3. 为每个候选保存配置、输入指纹、求解器版本、网格、物理时钟、水量台账、预热和数值检查。最终结果使用新的 `data/processed/hydrodynamics/runs/full_reach_vN/` 空目录。保留既有 `full_reach_v2` 及其对应源码版本的可追溯性，失败结果留在独立路径并保持未验收状态。
4. 检查静水平衡、干湿转换、最小水深、有限速度、预热收敛、水量和动态连通。优先沿用现有校验阈值。需要改阈值时说明数值依据及影响，不能因为场景表现不达标而放宽数值稳定性或数据完整性。

### C 在「全河段模拟」里呈现新结果

- 新运行通过验收后，经现有只读接口接入。显式选择并标明验收版本，让用户在同一入口切回 `full_reach_v2` 对照。切换运行时重建该运行自己的初始湿区缓存，取消旧请求并释放旧资源，严禁混用两个版本的高程、帧和统计。
- 方案一自然水面继续适用。暗绿为本运行展示起点已湿且当前仍湿，青蓝为本运行起点以后当前湿润。陆地淹没由模型网格水深和地形决定，着色器只负责画出来。低于现有 0.05 m 门槛时透明，前缘仅在实际湿侧窄幅提亮。保留水深、流速定量色标和模型速度驱动的跟踪点。
- 默认视角能同时看到主河槽及代表性城区低地，并提供同一相机的基流、首次漫岸、洪峰和退水对照。加入「两岸新增淹没面积」或等价轨迹，单位 km²，点位查询展示该处从干到湿的水深与流速过程。深度、统计和跟踪点与波头共用模型时钟。
- 解决播放慢的问题。新增快速观察预设，默认以约 18 秒走完一轮，验收目标 15–24 秒，便于看清第一次越岸和回落。按实际物理历时换算基础倍率，保留慢速、暂停、拖动、重播及速查洪峰。时间轴标模型历时和播放倍率。快速播放检查插值、帧缓存和粒子子步，防止拖动后飞点、跳湿区或把时间压缩当作实测流速。

## 三、验收口径

| 类别 | 必须交代的证据 |
| --- | --- |
| 真实的模型漫岸 | 固定 v2 的理想河槽外缘及过渡带为对照范围。若网格变化，明确共同比较区和面积计算方式。以展示 0 h 原本 (h<0.05) m、位于该范围之外且当前 (h≥0.05) m 的单元计算新增面积。另报 (h≥0.10) m 的面积作对照。至少两处代表性低地有连续湿单元、越岸后的模型连通证据及可核对的水深增长时序。用相邻单元水深、水位、速度和通量方向辨别主河槽进水、端界倒灌及单格数值异常。 |
| 变化清晰 | 同口径并列旧、新运行的峰值新增面积、退水减少面积和峰值时刻。建议将两岸新增湿区峰值 ≥5 km² 作为教学展示目标，明显退水，并在至少两个连续输出帧看到低地仍湿。该值是本版提出的验收目标。达不到时如实给出最好的稳定结果、差距与原因，保留未达标状态。 |
| 空间和时间 | 初始、涨水、峰值、退水同镜头截图及一段快速录屏。报告至少两个起初干燥的陆地点位在求解结果与实际网页中的数值一致，区分回落干地与仍湿的残余积水。验证常速与快放、暂停、拖动、重播、不连续加载、缓存淘汰及资源释放。 |
| 性能和回归 | 运行 `frontend` 的 `npm.cmd run build`、相关逻辑和实际浏览器验收，记录平均帧率、拖动响应、整轮实测用时及 WebGL 错误。桌面 1920×1080 的平均帧率目标至少 30 fps。保留静态 S01–S11、「陆地淹没」独立演示、降雨、旧水动力版本以及底图和原分析模式。 |
| 数据保护 | 比较原始 DEM、Phase 2/3、S01–S11、旧水动力帧、静态连续演示及新运行来源指纹。新录屏、截图、参数、台账和验收写入新的独立路径。不得下载新数据、安装依赖、修改系统、提交或推送 Git。 |

阶段完成后最小同步 README、TASKS，并交付可点击的演示、选定运行号、与 `full_reach_v2` 的比较、模型检验、城区近景和录屏链接。验收后能分辨哪些陆地被模型淹到、从哪条路径进水以及在哪个阶段退水。
