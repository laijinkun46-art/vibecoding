# 南宁邕江全河段洪水动态情景交付与验收

适用版本 `full_reach_v2`。2026 年 11 月 24 日（北京时间）。

**基于真实地形和假设参数的洪水动态情景模拟。** 面向课程设计，覆盖现有研究区内 33.682 km 邕江主线及两岸。流量、尾水、理想河槽和糙率均为教学设定，数值验收针对本情景的稳定性、守恒和展示。真实河床、观测水位和历史事件校准仍缺资料。

上位要求见 [全河段水动力模拟总规范](YONGJIANG_HYDRODYNAMIC_SIMULATION_SPEC.md) 与 [本轮端到端执行指令](CONSTRAINT_END_TO_END_EXECUTION_20261124.md)。地形与假设依据见 [全河段地形准备](PHASE_4_1_2_FULL_REACH_TERRAIN_REVIEW.md) 和 [扩展 4.1.4 情景评审](CONSTRAINT_FULL_REACH_SCENARIO_20261124.md)。

## 演示入口和用法

打开 [本机 WebGIS](http://127.0.0.1:5173/)，切换到「全河段模拟」。时间轴从预热结束后的基流状态开始。可播放、暂停、重播、拖动时间轴，或选择 0.5、1、2 倍。选择水深或流速着色，点击研究区内的地图位置可查看当前水深、流速和两条过程曲线。「静态情景」仍可查看 S01–S04 及 CHM_PRE 历史降雨。

复用同一个 Cesium Viewer。动态模式在研究区内采用模型地形，区外沿用既有地形。屏幕粒子的方向和相对移动速度取自模型水平速度分量，干区不显示水流。相邻输出帧做显示插值，湿深门槛为 0.05 m。帧间淹没面积随有效单元的湿干转换估算，输出时刻读取模型统计。时间轴及三维拉伸均不更改模型物理量。网页沿用原地形的本地显示约定，模型存档和查询高程以 EGM2008 为准。跨数据源比较绝对高程前仍需核对垂直基准。默认使用卫星影像，影像服务不可用时可切到「本地概览」。

## 全河段计算及情景参数

| 项目 | 本次采用 |
| --- | --- |
| 域与数据 | 使用既有 AOI 与 Phase 2 FABDEM。模型域约 286.849 km²，投影 EPSG:32649，米制高程沿用 EGM2008。WGS84 范围为 108.23–108.44°E、22.73–22.85°N。 |
| 网格及边缘地形 | 11,654 个控制体、23,988 条通量边。近河约 60 m，外围按离河距离逐级粗化至约 120–490 m。全部单元中心取到有效 DEM，无需近邻回退，也未扩展 AOI。 |
| 理想河床 | 180 m 底宽、7 m 设计岸深、3H:1V 岸坡，外接 60 m 过渡。西端床高 56.5 m，W→E 合成纵坡 0.00005 m/m。共 2,982 个单元降低地形，只写入模型派生结果。原 FABDEM 的 63 m 平台仅用于地形判读。 |
| 糙率及初始状态 | 槽内、洪泛区曼宁糙率分别为 0.032、0.065 s/m¹ᐟ³，过渡区混合。初始理想水深 4 m、槽内约 0.533 m/s，两岸从干地开始。 |
| W006 及 E012 | 情景规定 W→E。W006 按总流量分配给槽口，预热基流 409 m³/s，展示第 18 小时达 4,000 m³/s，再回落至基流。E012 采用 EGM2008 尾水 58.816–68.816 m，展示第 21 小时达峰，允许受尾水影响的回流。OSM 几何里程仅用于定位。 |
| 侧界及支流 | 模型将 84 段既有周界的设定映射到 196 条外部计算边。西、东槽口各 3 条通量边，98 条低地及槽口两侧边满足湿深条件时仅向外泄水，剩余 92 条暂按无穿越处理。计算结束时的累计侧泄量约 5,570 万 m³，未知区外来水和朝阳溪 347 m 河线缺口会影响展宽。 |
| 降雨 | 采用独立合成来流，域内降雨为 0。现有 CHM_PRE 逐日降雨仅在静态模式提供历史背景，当前未找到验收通过的扩展 4.1.3 模型降雨强迫。 |
| 时间 | 36 h 预热、60 h 展示，原始输出共 193 帧（含预热），网页 121 帧，间隔 30 min。模型内部按稳定性限制自适应步进，共 175,000 步。 |

60 m 近河网格无法分辨所有窄堤、巷道和支沟。理想河床和边界设置会影响涨水到达时间及淹没形状。模型的结果适用于当前教学设定，不能外推为精确的历史淹没线或实际防洪结论。替代尾水、来流、糙率和侧界仍可成组复算，当前只验收基础情景。

运行参数见 [参数快照](../data/processed/hydrodynamics/runs/full_reach_v2/parameters.json)；其中 4.1.4 原 `basis` 对 24 h 预热、总时钟 42 h 来流峰值的文字仍可追溯至初稿。v2 实际使用 `run_adjustment` 和更新后的数值序列，对应 36 h 预热、总时钟 54 h 来流峰值（展示第 18 小时）。预热延期使各来洪节点同向后移 12 h，展示历时未变。84 段周界的来源与基准情景设定见 [边界分段评估](../data/processed/hydrodynamics/preparation/full_reach_scenario_v1/boundary_assessment.csv)。

## 数值验收与结果

本机现有 Python 环境未能导入 ANUGA。复用已有 GIS Python 和 Windows C# 编译器，实现保守型二维有限体积浅水方程离线求解。模型求解水深与两个水平动量，包含水静力重构、Rusanov 数值通量、干湿转换和曼宁摩阻。水静力重构按原方法构造，算例独立检查静水平衡。[Audusse 等人的方法原文](https://perso.math.u-pem.fr/bouchut.francois/publications/hydroproj_published.pdf)

| 检查 | 实际结果 |
| --- | --- |
| 台阶静水与干床溃坝 | 静水水深变化 0 m，最大残余流速 1.54×10⁻¹⁶ m/s；溃坝湿单元 25→144，两个闭域算例的水量残差均为 0。 |
| 开边界补充小算例 | 800 m³ 规定入流的误差约 7×10⁻¹³ m³；E 端抬高尾水触发有符号回流；低于湿深门槛的干侧界外流为 0。 |
| 粗网格试算 | 全域 3,329 个单元试算 2 h，最大相对水量误差 1.52×10⁻¹⁵。 |
| 预热门槛 | v1 预热 24 h，末 2 h 通量不平衡约 7.37%，因此隔离。v2 预热 36 h，末 2 h 通量不平衡 1.54%、库容变化比例 0.175%，分别低于 5% 和 2%。 |
| 完整情景的水深、速度和水量 | 最小原始水深 0 m，全程最大流速 1.593 m/s，最大相对水量残差 3.30×10⁻¹⁴；全程无额外水量修正。 |
| 漫岸和退水 | ≥0.05 m 的湿面积由 7.494 km² 增至 13.373 km²，末帧降到 8.349 km²。理想河槽及过渡以外的湿面积峰前增加 2.128 km²、峰后减少 2.001 km²，均超过各 1 km² 的预设门槛。 |
| 峰值与沿程涨水 | 漫岸范围在展示第 22.5 h 达峰，峰帧最大模型水深约 15.87 m。几何里程 2.5 至 32.5 km 每隔 5 km 抽样，水深首次比基流增加 ≥1 m 的时刻依次为 9.5、10.5、11、12、12.5、12.5、12 h。尾水也能带动东端涨水，这些时刻是各点响应。 |
| 来源与结果回读 | 14 项原始输入、Phase 2 和 Phase 3 各 21 项、C03 旧成果及全河段输入清单按既有 SHA256 核对；123 项网页资源重新核对 SHA256，全部 121 帧独立对照原始水深、水面高程和两个速度分量。 |

岸外示例点 108.36035°E、22.78491°N 距主线约 309 m。该单元在基流为干地，展示第 20.5 h 首个湿帧为 0.53 m，第 22.5 h 水深 1.32 m、流速 0.31 m/s，第 26.5 h 回到 0.05 m 门槛以下。可用匿名点位接口对照。[该点过程数据](http://127.0.0.1:8000/api/hydrodynamics/runs/full_reach_v2/series?lon=108.36035&lat=22.78491)

原始二进制保存各单元的水深和水平动量及积分水量台账。网页帧分别保存水深、水面高程和水平速度分量，查询索引指向相同的模型单元。区外查询独立返回区外状态，区内干地使用真实计算状态。已预热且通过阈值的 `full_reach_v2` 才发布到结果 API，试算和未通过的 v1 不在结果列表内。[结果清单](../data/processed/hydrodynamics/runs/full_reach_v2/manifest.json) · [数值验收](../data/processed/hydrodynamics/runs/full_reach_v2/validation.json)

## 浏览器验收

在本机 Edge 实际加载 Cesium。核对基流、洪峰、退水三帧及卫星底图画面，验证 API 和区外点、播放与暂停、峰值拖动、流速着色、播放倍率、重播、地图点查询、过程曲线和可见状态切换逻辑。生产构建成功。旧模式的 14 项地形、28 项网页资源及 17 项动画逻辑检查通过。补充实测 0.5×、1×、2× 每秒推进约 727、1,467、2,942 模拟秒，切到卫星底图后在洪峰点击得到 9.47 m 水深、0.43 m/s 流速及同步曲线。

桌面 1920×1080，i7-14700HX 与 RTX 4070 Laptop GPU（ANGLE D3D11），硬件加速 Edge 自动化浏览器，本机底图，320 个粒子。模型帧预热后，120 秒内测得 15,602 次 Cesium 呈现，平均 130.02 fps，帧间隔 P95 为 8.40 ms，最大 10.20 ms，无超过 500 ms 的间隔。计数来自 Cesium 渲染事件，数值取决于本机、底图和图形环境。

600.02 s 稳定性检查通过。24 次拖动从发出到界面恢复可交互，中位 22.20 ms，最长 34.66 ms。前后主动垃圾回收后，JS 堆约 23.64→28.77 MB，DOM 节点均为 508。测试内无崩溃或未预期页面错误；屏蔽外部底图触发了一条预期网络中断日志。本轮记录了 JS 堆端点，GPU 显存及更长时间内存趋势未单独测量。结束时实测可切回旧静态模式并逐一切换 S01–S04。[浏览器验收记录](../outputs/hydro_full_reach_v2/browser_acceptance/browser.json)

## 复现与停止服务

[README](../README.md#全河段动态水动力演示)列出两个 PowerShell 终端的启动命令、当前 GIS Python 的全域复算命令及 Edge 浏览器回归命令。后端只监听 `127.0.0.1:8000`，生产预览只监听 `127.0.0.1:5173`。手动启动的服务可在各自终端按 Ctrl+C。此次保留的后台预览也可停止，在 PowerShell 先核实两个端口的监听进程，再结束本次启动的进程。

```powershell
Get-NetTCPConnection -LocalAddress 127.0.0.1 -LocalPort 5173,8000 -State Listen |
  Format-Table LocalAddress, LocalPort, OwningProcess
Stop-Process -Id 47504,43036,55048 -ErrorAction SilentlyContinue
```

停止命令中的 ID 对应本次前端进程、后端监听进程和后端启动器。电脑重启或已另行启动服务时，以当前监听的进程核对结果为准。只读结果 API 通过下列文件接入现有应用。没有额外的运行服务或前端结果副本。
