## 3. ANUGA必要性评估

### 3.1 结论与选择依据

现有connected_inundation计算“低于水位且从河道可达”的静态集合，没有连续方程、动量方程或物理时间。给四个水位绑定人为日期、用面积差除以3500ms、用搜索队列步数作传播时间，都不能得到可信流速。

若用户提供可复用的其他模型h/u/v成果，优先仅实现结果适配和可视化，无需为使用ANUGA重复计算；若没有外部成果且确需研究动力过程，建议新增ANUGA离线计算适配。它求解二维浅水方程，可输出水面与水平动量，适合评估本次洪水传播研究。官方依据：[ANUGA数学背景](https://anuga.readthedocs.io/en/latest/mathematical_background.html)、[官方文档入口](https://anuga.readthedocs.io/en/stable/)。

没有发现现有ANUGA求解模块或.sww成果；既有flood.py只保留静态方法，不把它包装成水动力算法。新模块复用GIS输入检查、坐标和统计工具。

### 3.2 接入形式与环境

采用“独立离线计算 → 校验与转换 → 现有FastAPI只读提供结果 → 现有前端展示”。首版不增加数据库、消息队列、微服务或网页实时求解任务。求解不放进HTTP请求或API启动过程，避免阻塞现有服务及依赖冲突。

现有API虚拟环境仅有FastAPI/Uvicorn，GIS依赖位于另一Python环境且曾有DLL定位/混用问题。ANUGA尚未安装，本轮不安装。后续先只读核对Windows/Python和现有包兼容情况，提出确切版本与依赖清单，经必要授权后使用项目隔离环境。不要修改系统PATH、替换现有Python或向现有GIS环境强行升级NumPy/GDAL；也不预先承诺安装一定成功。官方说明ANUGA含C/Cython扩展，安装路线应按实际环境验证：[安装文档](https://anuga.readthedocs.io/en/stable/installation/index.html)。

## 4. 数据链和结果约定

### 4.1 目录与不可覆盖规则

```text
已有 data/raw/、data/processed/phase2/、phase3/ 和 frontend/public/analysis/ 保持原样

拟增 data/scenarios/hydrodynamic_scenario.json       参数与输入清单，非观测数据
拟增 data/processed/hydrodynamics/<run_id>/
  原始ANUGA .sww                                   物理求解原始输出
  manifest.json                                    坐标、时间、变量、来源、哈希、检验状态
  frames/<frame_id>.bin                            供网页及点查询的规则网格帧
  statistics.json                                 面积、最大水深/速度与前锋等
```

run_id是每次计算的唯一标识，目录若已存在且含成果则拒绝覆盖。输出采用完整写入后再标记ready，失败结果不得出现在可浏览清单中。原始SWW、转换结果和验证报告分别留存；不因重跑删除旧数据，不将新成果写入phase2/phase3原目录。无需将大时序复制到frontend/public，现有FastAPI提供白名单文件。

### 4.2 manifest与变量

拟定manifest包含schema_version、run_id、kind（hydrodynamic_model_scenario或validated_hindcast）、validation_status、模型/求解器版本、代码版本、输入SHA256、参数、源文件、计算域、水平CRS、垂直基准、模型原点、时间语义和输出变量。validated_hindcast只在取得独立验证证据后允许。

- 水平计算继续用EPSG:32649，坐标单位m；明确UTM本地原点加回规则。网页定位使用WGS84；速度从投影网格x/y转换至地图局部东/北时考虑投影轴与局部方向差，不能把UTM米直接当经纬度。
- bed_elevation和stage单位m，使用一致且有依据的垂直基准；depth=max(stage-bed,0)；u/v为深度平均速度，单位m/s；speed=hypot(u,v)。ANUGA动量变量单位m²/s，与速度不同，转换需干湿与浅水保护。依据：[变量和单位](https://anuga.readthedocs.io/en/stable/setup_anuga_script/conventions.html)。
- 保留elevation、stage、xmomentum/ymomentum及其存储位置，不混用顶点与三角形中心值。实际SWW布局需按输出文件确认，不将文档示例shape写死；.sww是带网格及时间变量的NetCDF。依据：[SWW文件格式](https://anuga.readthedocs.io/en/stable/reference/file_formats.html)。
- t_seconds单调递增；时间原点若为假设，页面只显示模拟历时；若对应事件，附带UTC起点与北京时间显示。显式区分求解器内部步长、输出间隔、播放倍率和浏览器刷新率。
- 统一设置并记录h_dry、h_wet、velocity_protection、front_threshold等；近干地按求解器定义保护分母，不自行用任意极小数制造巨大速度。湿干、缺测、计算域外、无效速度分别编码。
- 平面真实数值始终不乘三维拉伸倍率；水面显示基于逐点stage，不能沿用所有动态帧一个常量waterLevel的旧静态几何。

### 4.3 网页帧与点查询

首版离线将模型输出按原地形可支持的尺度映射到规则网格，建议先试30～60m并依据精度/性能决定；新网格是展示与查询派生产品，不宣称提高原始分辨率。保留原始三角网SWW用于核查，不能跨堤防/干地随意平滑速度。

帧头信息由manifest统一定义：width/height、geotransform、每像元字段布局、字节序、float32精度和mask。可采用小端交错depth/u/v/stage四个Float32加独立uint8掩膜。网格四角、行序、偏移、NoData和字节长度均验证，文件需有SHA256。与当前728×457规模相近的一个四变量帧约5.32MB，加mask约0.33MB；100帧约565MB，不能整段一次加载浏览器。

FastAPI无需加载ANUGA或NumPy即可用标准库struct/mmap读取已导出的规则网格点值并提供文件响应。点查询先采用同一目标网格像元取样，响应注明nearest_cell、cell_id、cell_center、分辨率和位置偏移；不显示超出网格精度的小数假象。曲线与鼠标当前值必须用同一采样规则。若后续改三角网插值，要同时更新前后端及验证。

浏览器只保留相邻2～3帧并有内存上限，使用版本/请求序号与AbortController取消旧时刻请求。资源错误保留原有静态地图并明确错误状态，不用零填补缺测。动画中的向量空间插值仅在有效湿区内，不能跨无效掩膜；时间插值须标明“帧间插值”，湿干转换不无条件线性混合，保守隐藏无有效数据粒子。

## 6. 前端增量实现

### 6.1 复用现有交互

App.vue增加“静态情景 / 动态水动力”模式，默认仍可回到原静态流程。已有timeline区域扩展为物理时间轴，复用播放、暂停与滑杆；当前视觉0.5/1/2倍控制不能冒充物理播放，动态模式需单一模拟时钟驱动帧、水面、向量和粒子。真实时序未就绪时禁用动态播放并说明原因。

动态模式提供水深着色、流速着色、流向箭头、粒子轨迹四个开关；图例明确单位和显示阈值，水深/流速主色图互斥以免遮挡。已有静态两期变化继续保留；动态两期比较只能比较同run、同网格的帧。

MapViewer.vue在既有Viewer注册点击事件，优先拾取地理表面位置并转换WGS84，不从水面视觉拉伸高度反算水深。输出经纬度给App.vue发起series请求，添加同场景查询标记；卸载时释放事件和图元。快速连续点击取消旧查询，未加载或域外给出清晰状态。

AnalysisCharts.vue增加点位水深和速度随物理时间的曲线及当前时刻游标，分别用m和m/s轴或两幅图；保留原面积/降雨图，不混用降雨日期与假设历时。支持无值断线、位置/时间/数据来源提示和查看表格。

### 6.2 粒子必须按模型向量运动

对有效湿区在局部米制坐标积分dx/dt=u、dy/dt=v，再转换至Cesium世界坐标；粒子表面高度取stage并采用同一展示高度处理。保留速度幅值，不能先归一化方向再让所有粒子等速。采用中点法或RK2与子步长约束，防止跨过网格或堤防；播放倍率改变模拟历时推进量。

粒子在干地、域外、缺测速度或水深低于阈值时停止/消隐并在有效湿区重新播种；u=v=0时保持静止，不能用随机移动制造水流。方向箭头取逐帧向量，可显示回流，不由OSM节点顺序决定。

流场随时间变化时积分得到的是“迹线”（粒子实际经历的路径）；瞬时流线是固定某时刻向量场积分。首版显示动态粒子迹线并在界面清楚命名；若另加瞬时流线，必须固定该时刻场，不混称。现有视觉波纹仍可作为装饰，并独立标注，不用它估计粒子速度。

浏览器中后台暂停时冻结播放；恢复不补跑隐藏期间大量模拟时间，拖动时间轴后重置粒子历史。复用当前24fps按需刷新和2D/隐藏暂停策略；未来二维是否展示粒子可单独验证，不自动启用新刷新策略。粒子数量设上限，避免一次为每个栅格生成大量独立实体。

### 6.3 洪水前锋定义

水体局部速度m/s与洪水前锋传播速度m/s属于不同物理量，不能相互替代。建议先输出：

1. 初始干地的首次持续淹没时间：h跨越明确阈值且保持至少约定帧数，记录输出时间分辨率和到达区间。初始已湿河道不产生虚假“t=0到达”前锋统计；缺测与未到达分别标记。
2. 同一预先定义传播路径/断面上两个位置的到达时差：c=路径距离/到达时差。距离用米制沿程距离；时间差太小、到达次序异常、路径不可连通时不返回速度。
3. 对始终有水的邕江主槽，另定义相对于初始stage的涨水阈值或波峰到达，用于研究洪水波传播，并明确区别于岸上湿干前锋。先确认上游—下游方向，不照抄OSM节点顺序。
4. 全域首次到达栅格和逐时淹没范围可视化。复杂分汊、回流和退水区不凭两期边界最近距离自动给唯一法向前锋速度。

阈值、输出间隔和路径选择开展敏感性检查；30m网格和分钟输出不应宣称秒级/米级到达精度。未有真实物理时间时，本功能保持不可用。

## 8. 分阶段实施与验收

本轮停在方案完成。用户确认后，每次只推进一个可验收阶段，数据不足时不越过相应门槛。

1. **接口与数据契约阶段**：同步新范围，确认物理目标、结果来源与时间约定。优先读取用户已有模型成果；没有成果时，列清ANUGA依赖及缺失输入，先验证环境可行性。仅用明确标识的合成恒定向量场进行开发测试，不将测试数据作为历史洪水成果发布。
2. **计算与结果阶段**：取得或确认边界/初始/糙率假设后，以小计算域、短历时试运行；验证静水保持、质量平衡、干湿转换、非负水深、有限速度和时间步稳定。形成可追溯SWW和派生帧，记录耗时/峰值内存；未验证前不全区长时计算。
3. **现有前端接入阶段**：接入真实模型帧、物理时间、深度/速度/方向，复用旧地图和ECharts，新增点查询；无动态结果时旧功能仍可用。
4. **粒子与前锋阶段**：确认速度单位、投影转换、时间插值、掩膜和路径定义后增加迹线及前锋指标，实测性能并限制缓存与粒子数。
5. **综合验收阶段**：执行相关构建、Python与浏览器检查，桌面/窄屏/2D/3D/快速拖动/失败恢复；对输入哈希和原功能回归，保留数据与模型可信度声明。

必要的非镜像验证：

- 测试恒定场u=2m/s、v=0，模拟10s粒子应在米制平面东移20m；0.5/1/2倍改变墙钟耗时，不改变相同模拟时刻位置。静止场不移动，暂停不移动。
- 同时刻水深/速度色图、粒子、点曲线游标一致；快拖与连续点击不显示过期请求；NoData为null而非伪0；方向图不在零速/干地显示箭头。
- 可手算网格点和已知SWW样本验证坐标、深度/动量到速度转换、顶点/中心值位置、大小端、行序及掩膜；UTM点转经纬度再回投影误差在设定容差内。
- ANUGA基本解析/基准算例（例如静水平衡、公开标准溃坝算例）和质量守恒残差；CFL是数值稳定性条件，不等同模型准确率。质量残差阈值、网格/时间收敛误差和历史观测误差阈值需按试验目的预先设定并报告，不随结果临时放宽。
- 已知距离与到达时间的前锋算例，区分初始湿区、未到达、缺测和二次湿润；核查前锋速度不能直接等于hypot(u,v)。
- 原S01～S04面积、深度和三组变化保持原结果；DEM、CHM_PRE、OSM输入哈希保持不变；只创建一个Viewer；旧API可用。
- 后续需要npm构建时，使用现有 `npm.cmd run build`（在frontend目录），该命令会执行Cesium资源复制；本轮未运行。GIS验证尽量写入该run的新报告，不覆盖旧阶段验收记录。

## 9. 主要风险和交付判断

| 风险 | 对策与可交付边界 |
| --- | --- |
| 缺边界和实测验证却宣称2024复现 | 显式模型假设与validation_status；不展示未经验证的精度标签 |
| 地表DEM替代河床、研究区边界过近 | 仅作起点，补足河床/边界或承认教学情景；禁止靠加密插值“提升精度” |
| EGM2008与椭球高、站点水尺基准不一致 | 离线统一物理高程；展示声明沿用；精密叠合需独立基准转换证据 |
| 湿干边缘速度爆大、粒子穿堤或跨干地 | 保留求解器保护、有效掩膜、受限插值和子步长；异常数据不得渲染成真结果 |
| 计算依赖破坏API/GIS环境 | 专用计算进程与依赖清单，FastAPI只读结果；不修改系统环境 |
| 帧数量与粒子令页面卡顿 | 小范围试验、2～3帧缓存、粒子上限、按需刷新和异步取消 |
| 已有用户修改与新代码冲突 | 开始实施前重新读取差异并基于当前文件做最小补丁，不还原/覆盖旧改动 |
| 新功能误伤旧情景与图表 | 模式隔离、旧数据哈希/数值回归、保留静态回退 |
| 将动画插值称观测，将迹线称瞬时流线 | 清楚标注模型帧、插值、粒子迹线和统计含义 |

当前可确认的交付是审计与可实施的增量设计；不能确认现有资料足以复现2024洪水真实流速。建议下一步先确认是否接受“未校准二维水动力情景研究”，或提供已存在的动态成果/边界与验证资料，再开展对应单阶段。确认前不进行代码升级、安装、下载或计算。
